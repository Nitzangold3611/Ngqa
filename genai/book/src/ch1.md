# פרק 1 — מבוא לבינה מלאכותית יוצרת בבדיקות תוכנה
<p class="en">Introduction to Generative AI for Software Testing</p>

הפרק הראשון מניח את היסודות: מה זו בינה מלאכותית יוצרת (GenAI), איך מודל שפה גדול (LLM) "קורא" טקסט ומייצר תשובה, מאילו שלבים התפתח התחום, ואילו סוגי מודלים קיימים. בסוף הפרק נראה איך כל זה מתחבר לעבודה היומיומית של בודק התוכנה.

## 1.1 יסודות ה-GenAI ומושגי מפתח

### מהי בינה מלאכותית יוצרת?
**בינה מלאכותית יוצרת (Generative AI)** היא תחום בבינה מלאכותית שמשתמש במודלים גדולים שאומנו מראש (Pre-Trained Models) כדי ליצור **תוכן חדש**: טקסט, קוד, תמונות, קול, וידאו ומסמכים. בניגוד למערכות שרק מסווגות או חוזות, מודל יוצר מייצר תוצר שלא היה קיים קודם.

דוגמה מעולם הבדיקות: מזינים דרישת מערכת למודל, ומקבלים ממנו טיוטה של מקרי בדיקה.

### מהו LLM?
**LLM (Large Language Model — מודל שפה גדול)** הוא מודל בינה מלאכותית שאומן על כמויות עצומות של טקסט — ספרים, אתרים, קוד ומסמכים — כדי להבין שפה טבעית ולייצר אותה. מודל כזה יודע להבין שפה, ליצור טקסט, לענות על שאלות, לכתוב קוד ולסכם מידע.

דוגמאות מוכרות: ChatGPT של OpenAI, ‏Claude של Anthropic, ‏Gemini של Google ו-Copilot של Microsoft.

### איך LLM עובד?
תהליך הליבה שבו מודל מעבד קלט ומייצר פלט עובר חמישה שלבים:

1. **Prompt (הנחיה)** — הטקסט שהמשתמש שולח למודל.
2. **Tokenization (טוקניזציה)** — פירוק הטקסט ליחידות קטנות.
3. **Embeddings (ייצוגים מספריים)** — הפיכת כל יחידה לווקטור של מספרים.
4. **Transformer Model** — עיבוד הווקטורים והבנת ההקשר.
5. **Generated Response (תגובה)** — המודל מייצר את התשובה, יחידה אחר יחידה.

### GenAI בעולם הבדיקות
מודל שפה יכול לקבל סיפור משתמש או דרישה ולהחזיר מקרי בדיקה וקריטריוני קבלה. השימושים המרכזיים בתהליכי QA:
- **ניתוח דרישות** — איתור עמימות, חוסרים וסתירות.
- **יצירת מקרי בדיקה** ו**יצירת נתוני בדיקה**.
- **כתיבת תסריטי בדיקה** לאוטומציה.
- **ניתוח תקלות** — סיווג, סיכום ואיתור דפוסים.
- **יצירת בודקה (Testware)** — תוכניות, דוחות ומסמכים נלווים.

### מושגי היסוד
#### טוקניזציה (Tokenization)
טוקניזציה היא פירוק טקסט ליחידות קטנות שנקראות **Tokens** — יחידות העיבוד הבסיסיות של המודל. לדוגמה, המשפט ‎"Generate test cases for login page"‎ מתפרק ל-6 טוקנים, וכל אחד מהם מעובד בנפרד. כל מילה, סימן פיסוק ואפילו רווח יכולים להפוך לטוקן.

למה זה חשוב?
- **עלות** — ככל שיש יותר טוקנים, השימוש יקר יותר.
- **מהירות** — מספר הטוקנים משפיע על זמן התגובה; פחות טוקנים = עיבוד מהיר יותר.
- **מגבלה** — לכל פנייה יש תקרה של טוקנים.

#### ייצוגים מספריים (Embeddings)
**Embedding** הוא ייצוג מתמטי של טוקן כווקטור מספרי. כל מילה מקבלת מיקום ב"מרחב סמנטי" רב-ממדי, והמיקום מבטא את המשמעות שלה. מילים עם משמעות קרובה — למשל Car, ‏Vehicle ו-Automobile, או Test Case, ‏Test Script ו-Test Scenario — מקבלות ווקטורים קרובים. מילה רחוקה במשמעות, כמו Database, נמצאת רחוק מהן. כך המודל מבין קשרים ומשמעויות, ולא רק מילים בודדות.

#### מודל הטרנספורמר (Transformer)
**Transformer** היא ארכיטקטורת הליבה של רוב מודלי השפה המודרניים. היא:
- מבינה את **ההקשר הכולל** של המשפט, לא רק מילה בודדת;
- מזהה **קשרים בין מילים** גם כשהן רחוקות זו מזו;
- **מייצרת תוכן** — טקסט, קוד ומסמכים — על בסיס ההקשר.

בלב הטרנספורמר נמצא **מנגנון הקשב (Attention Mechanism)**, שקובע לאילו חלקים בקלט "לשים לב" בכל שלב של יצירת התשובה.

#### התנהגות לא-דטרמיניסטית
אותו Prompt עשוי להחזיר תשובות שונות בכל הרצה. המודל אינו מחשבון שמחזיר תוצאה קבועה, אלא **מערכת הסתברותית**: בכל שלב הוא בוחר את ההמשך מתוך כמה אפשרויות סבירות. לבודקים זה חשוב במיוחד — צריך לבדוק את הפלט ולא להניח שהוא יחזור על עצמו.

#### חלון ההקשר (Context Window)
**Context Window** הוא כמות הטוקנים המקסימלית שהמודל יכול לקחת בחשבון בבת אחת — הקלט, ההיסטוריה של השיחה והפלט יחד. לדוגמה, מסמך דרישות, יומן תקלות ודוח בדיקות יכולים להיכנס יחד לחלון אחד, והמודל ינתח אותם במשותף.

| חלון הקשר גדול — יתרונות | חלון הקשר גדול — חסרונות |
|---|---|
| ניתוח מסמכים ארוכים בבת אחת | עלות גבוהה יותר (יותר טוקנים) |
| הבנה עמוקה יותר של תלויות ומשמעויות | זמן עיבוד ארוך יותר |
| תשובות מדויקות יותר, פחות אי-הבנות | מורכבות חישובית ודרישות משאבים גבוהות |

### 1.1.1 ספקטרום הבינה המלאכותית
GenAI הוא שיאו של תהליך שנמשך עשורים, וכל שלב נבנה על קודמו:

| תקופה | שלב | עיקרון |
|---|---|---|
| 1950–1980 | בינה מלאכותית סימבולית (Symbolic AI) | חוקים שכתבו מומחים (Rule-Based) |
| 1980–2010 | למידת מכונה קלאסית (Machine Learning) | מודלים שלומדים מנתונים |
| 2010 ואילך | למידה עמוקה (Deep Learning) | רשתות עצביות |
| 2020 ואילך | בינה מלאכותית יוצרת (GenAI) | יצירת תוכן חדש |

**Symbolic AI** — מערכת שמבוססת על חוקים מוגדרים מראש, למשל: "אם אורך הסיסמה קטן מ-8 — דחה אותה", "אם היו יותר מ-3 ניסיונות כניסה — נעל את החשבון". היתרון: **שקיפות מלאה** — אפשר לעקוב אחרי כל החלטה. החיסרון: קושי להתמודד עם מידע מורכב, לא מובנה או מצבים לא צפויים.

**למידת מכונה קלאסית** — שלושה שלבים: הכנת נתונים (איסוף, ניקוי ועיצוב), בחירת מאפיינים (המשתנים שהכי משפיעים על החיזוי), ואימון המודל. דוגמה מהבדיקות: חיזוי אילו רכיבים צפויים להיכשל בגרסה הבאה, על סמך נתוני עבר.

**למידה עמוקה** — מבוססת על **רשתות עצביות** (שכבת קלט, שכבות נסתרות ושכבת פלט) שמחקות באופן גס את מבנה המוח. היא מטפלת בטקסט, תמונות, קול ווידאו, והיא הבסיס שעליו נבנה ה-GenAI.

**GenAI** — השלב המתקדם ביותר: רשתות עצביות עמוקות שמייצרות תוכן חדש ומורכב. אין צורך לאמן מודל חדש לכל משימה — **מודל אחד, שימושים רבים**.

| קריטריון | Symbolic AI | ML | Deep Learning | GenAI |
|---|---|---|---|---|
| תלות בחוקים | גבוהה | נמוכה | נמוכה | נמוכה |
| תלות בנתונים | נמוכה | גבוהה | גבוהה מאוד | גבוהה מאוד |
| יצירת תוכן | ✗ | ✗ | מוגבלת | ✓ |
| שימוש ב-QA | מוגבל | בינוני | גבוה | גבוה מאוד |

### 1.1.2 LLM לעומת SLM
לצד מודלי השפה הגדולים קיימים גם **מודלי שפה קטנים (SLM — Small Language Models)**: ממוקדים, יעילים וקלים.

| | LLM — מודל שפה גדול | SLM — מודל שפה קטן |
|---|---|---|
| גודל | גדול | קטן |
| ביצועים | גבוהים ורחבים | ממוקדים ומהירים |
| עלות | גבוהה | נמוכה |
| משאבים | רבים ומורכבים | מעטים |
| מתאים ל- | משימות מורכבות ורחבות | פריסה מהירה וחסכונית, משימה מוגדרת |

**תרגיל 1.1.2 — טוקניזציה והערכת משאבים:** בעזרת OpenAI Tokenizer בודקים כמה טוקנים יש במשפט בעברית ובמשפט באנגלית, משווים טקסטים ("QA Engineer", ‏"Quality Assurance Engineer", ‏"מהנדס בדיקות תוכנה") ובוחנים איך אורך הפרומפט משפיע על העלות. המסקנות: לא כל מילה היא טוקן אחד; עברית "צורכת" לרוב יותר טוקנים מאנגלית; ופרומפט ארוך יותר לא תמיד נותן תוצאה טובה יותר — צריך לאזן בין איכות לעלות.

### 1.1.3 שלושת סוגי מודלי השפה
התפתחות המודלים עוברת שלושה סוגים: **Foundation ← Instruction-Tuned ← Reasoning**.

**מודלי יסוד (Foundation Models)** — אומנו על מאגרי מידע עצומים (ספרים, אתרים, קוד, מאמרים) בלי משימה ספציפית אחת. הם כלליים, גמישים ורב-תחומיים, ומשמשים בסיס לשאר המודלים — אבל כדי לבצע משימה מסוימת בצורה מיטבית הם דורשים **כוונון נוסף (Fine-Tuning)**.

**מודלים מכווננים להוראות (Instruction-Tuned)** — מודלי יסוד שעברו Fine-Tuning על דוגמאות של הוראות ותשובות. הם מבינים פקודות בשפה טבעית ומגיבים בצורה עקבית ומובנית, ולכן מתאימים לשימוש מעשי מיידי — למשל: "צור מקרי בדיקה לפונקציית ההתחברות".

**מודלי הסקה (Reasoning Models)** — מתמחים בחשיבה מורכבת: מפרקים בעיה לשלבים לוגיים עוקבים (Chain of Thought), מסיקים מסקנות מהקשר חלקי ומזהים אנומליות. מתאימים במיוחד לתכנון בדיקות, לניתוח שורש תקלה (Root Cause Analysis) ולניתוח סיכונים.

| מאפיין | Foundation | Instruction-Tuned | Reasoning |
|---|---|---|---|
| כלליות | **גבוהה** | בינונית | נמוכה |
| הבנת הוראות | בינונית | **גבוהה** | גבוהה |
| פתרון בעיות מורכבות | בינוני | בינוני | **גבוה** |

### 1.1.4 מודלים רב-מודאליים
**מודל רב-מודאלי (Multimodal)** מעבד ומשלב כמה סוגי מידע בו-זמנית: טקסט, תמונה, קול ווידאו.

**Vision-Language Models** משלבים הבנת תמונה עם הבנת שפה:
- **קלט חזותי** — צילומי מסך, שרטוטי ממשק (Wireframes) ואבות-טיפוס (Mockups); המודל מזהה כפתורים, שדות ופריסה.
- **קלט טקסטואלי** — סיפורי משתמש, דרישות ומפרטים; המודל מבין את ההקשר העסקי.
- **פלט** — מקרי בדיקה לממשק, מועמדים לתקלות (Defect Candidates) וקריטריוני קבלה משופרים.

דוגמה: מזינים סיפור משתמש ושרטוט של המסך יחד, והמודל מחזיר קריטריוני קבלה, מקרי בדיקה ורשימת תקלות אפשריות (למשל שדה שמופיע בדרישה וחסר בשרטוט).

## 1.2 מינוף GenAI בבדיקות תוכנה
מודלי שפה מסייעים לאורך כל מחזור חיי הבדיקות: יצירת תוכן בדיקות, ניתוח מידע ותקלות, הבנת דרישות והקשר, המלצות לשיפור תהליכים, תרגום בין שפות ופורמטים, וסיכום תוצאות ודוחות.

### 1.2.1 יכולות הליבה של LLM למשימות בדיקה
- ניתוח דרישות מערכת;
- יצירת מקרי בדיקה והגדרת **תוצאות צפויות**;
- יצירת נתוני בדיקה;
- בניית חומרי בדיקה (בודקה);
- ניתוח תוצאות בדיקה;
- תמיכה באוטומציה — כתיבה ותחזוקה של תסריטים.

### 1.2.2 צ'אטבוט לעומת אפליקציה מבוססת LLM
| | צ'אטבוט | אפליקציה מבוססת LLM |
|---|---|---|
| ממשק שיחה | כן | לא בהכרח |
| שימוש ידני | כן | חלקי |
| אוטומציה | נמוכה | גבוהה |
| אינטגרציה | מוגבלת | גבוהה — משולבת בתהליכים, ב-APIs ובמערכות QA |

## דגשים לבחינה
- GenAI מבוסס על Deep Learning, ו-Transformer הוא הבסיס לרוב ה-LLMs.
- LLM עובד באמצעות Tokens; ‏Embeddings מייצגים משמעות באופן מספרי — אל תתבלבלו ביניהם.
- חלון ההקשר מוגבל בגודלו.
- סדר ההתפתחות: Foundation ← Instruction-Tuned ← Reasoning.
- מודלים רב-מודאליים משלבים טקסט, תמונה ומידע נוסף.
- טעויות נפוצות: לחשוב ש-LLM תמיד מחזיר אותה תשובה, או שהוא תמיד צודק.

## מושגים והסברים
| מושג | הסבר |
|---|---|
| Generative AI — בינה מלאכותית יוצרת | בינה מלאכותית שמייצרת תוכן חדש (טקסט, קוד, תמונות) בעזרת מודלים שאומנו מראש |
| LLM — מודל שפה גדול | מודל שאומן על כמויות עצומות של טקסט כדי להבין ולייצר שפה טבעית |
| SLM — מודל שפה קטן | מודל שפה קטן וממוקד: זול ומהיר יותר, מתאים למשימות מוגדרות |
| Prompt — הנחיה | הטקסט שנשלח למודל: הוראה, שאלה או קלט |
| Token — טוקן | יחידת העיבוד הבסיסית של המודל: חלק ממילה, מילה או סימן |
| Tokenization — טוקניזציה | פירוק טקסט לטוקנים לפני העיבוד |
| Embedding — ייצוג מספרי | ווקטור מספרי שמייצג את משמעות הטוקן; משמעויות קרובות = ווקטורים קרובים |
| Transformer | ארכיטקטורת הליבה של מודלי השפה, שמבינה הקשר בעזרת מנגנון קשב |
| Attention Mechanism — מנגנון קשב | הרכיב שקובע לאילו חלקים בקלט המודל "שם לב" בכל שלב |
| Context Window — חלון הקשר | כמות הטוקנים המקסימלית שהמודל מעבד בבת אחת |
| Non-Deterministic — לא-דטרמיניסטי | אותה הנחיה עשויה להחזיר תשובות שונות בכל הרצה |
| Symbolic AI | בינה מלאכותית מבוססת חוקים שנכתבו ידנית; שקופה אך לא גמישה |
| Machine Learning — למידת מכונה | מודלים שלומדים דפוסים מנתונים |
| Deep Learning — למידה עמוקה | למידת מכונה בעזרת רשתות עצביות רב-שכבתיות |
| Foundation Model — מודל יסוד | מודל כללי שאומן על מידע עצום; בסיס למודלים אחרים |
| Fine-Tuning — כוונון | אימון נוסף של מודל קיים על דוגמאות ממוקדות למשימה |
| Instruction-Tuned Model | מודל שכוונן להבין ולבצע הוראות בשפה טבעית |
| Reasoning Model — מודל הסקה | מודל שמפרק בעיות מורכבות לשלבים ומסיק מסקנות |
| Multimodal Model — מודל רב-מודאלי | מודל שמעבד כמה סוגי מידע: טקסט, תמונה, קול, וידאו |
| Vision-Language Model | מודל רב-מודאלי שמשלב הבנת תמונה והבנת שפה |
| Testware — בודקה | כל התוצרים של תהליך הבדיקות: תוכניות, מקרי בדיקה, נתונים, תסריטים ודוחות |
| LLM-Powered Application | מערכת שמשלבת מודל שפה בתהליכים ובכלים, מעבר לממשק שיחה |

## בקצרה — במילים פשוטות
<div class="plain">

בינה מלאכותית יוצרת היא תוכנה שלמדה מכמות עצומה של טקסטים, ולכן היא יודעת "לכתוב" בעצמה — תשובות, קוד, מקרי בדיקה ועוד. כדי לעשות את זה היא מפרקת כל טקסט לחתיכות קטנות (טוקנים), הופכת אותן למספרים שמייצגים משמעות, ומחשבת מה הכי סביר שיבוא אחר כך.

כמה דברים כדאי לזכור: לכל מודל יש גבול לכמות הטקסט שהוא "רואה" בבת אחת; הוא לא תמיד עונה אותו דבר על אותה שאלה; והוא לא תמיד צודק. יש מודלים כלליים, מודלים שמבינים הוראות, ומודלים ש"חושבים" צעד אחר צעד — ויש גם מודלים שמבינים תמונות, למשל צילום מסך של אפליקציה.

לבודק, כל זה אומר עוזר חזק: אפשר לבקש ממנו לנתח דרישות, להציע מקרי בדיקה ונתוני בדיקה ולסכם תקלות. אבל התוצרים שלו הם טיוטה — הבודק עדיין אחראי לבדוק ולאשר אותם.

</div>
